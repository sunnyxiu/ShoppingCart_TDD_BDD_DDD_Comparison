# 自動化腳本使用說明

### 1. collect_metrics.py - 收集程式碼指標

**功能**：自動收集程式碼行數、複雜度、函數數量等指標

**使用方式**：

```bash
cd comparison/scripts

# 收集單一版本
python collect_metrics.py --version tdd
python collect_metrics.py --version bdd
python collect_metrics.py --version ddd

# 收集所有版本
python collect_metrics.py --all
```

**輸出**：
- 更新 `comparison/metrics/code_metrics.csv`
- 在終端顯示收集到的指標

**範例輸出**：
```
📊 開始收集 TDD 版本的程式碼指標...

==================================================
📊 TDD 版本程式碼指標
==================================================
📅 日期：2024-11-14
📝 程式碼行數：150
🧪 測試行數：450
📖 文件行數：50
🔄 圈複雜度：8.5
🔢 函數數量：13
==================================================

✅ TDD 指標已儲存到 ../comparison/metrics/code_metrics.csv
```

**注意事項**：
- 需要在 `comparison/scripts/` 目錄執行
- 會自動讀取 `../{version}-version/src/` 的程式碼
- 如果沒有安裝 cloc 或 radon，會使用簡單的計算方式

### 2. generate_charts.py - 生成圖表

**功能**：從 CSV 資料生成視覺化圖表

**使用方式**：

```bash
cd comparison/scripts

# 生成所有圖表
python generate_charts.py

# 生成特定圖表
python generate_charts.py --chart time        # 開發時間圖表
python generate_charts.py --chart coverage    # 測試覆蓋率圖表
python generate_charts.py --chart complexity  # 程式碼複雜度圖表
python generate_charts.py --chart bug         # Bug 統計圖表
```

**輸出**：
- `comparison/analysis/charts/development_time_chart.png`
- `comparison/analysis/charts/code_coverage_chart.png`
- `comparison/analysis/charts/complexity_comparison.png`
- `comparison/analysis/charts/bug_statistics.png`

**範例輸出**：
```
==================================================
📊 開始生成所有比較圖表
==================================================

📊 生成開發時間比較圖...
✅ 開發時間圖表已儲存：../comparison/analysis/charts/development_time_chart.png

📊 生成測試覆蓋率比較圖...
✅ 測試覆蓋率圖表已儲存：../comparison/analysis/charts/code_coverage_chart.png

📊 生成程式碼複雜度比較圖...
✅ 程式碼複雜度圖表已儲存：../comparison/analysis/charts/complexity_comparison.png

==================================================
```

**生成的圖表**：

1. **development_time_chart.png** - 包含：
   - 總開發時間比較（柱狀圖）
   - 各功能開發時間分布（分組柱狀圖）

2. **code_coverage_chart.png** - 包含：
   - 最終覆蓋率比較（分組柱狀圖）
   - 覆蓋率變化趨勢（折線圖）

3. **complexity_comparison.png** - 包含：
   - 程式碼與測試行數比較
   - 平均圈複雜度比較

   - 測試/程式碼比例

4. **bug_statistics.png** - 包含：
   - Bug 總數比較
   - Bug 嚴重性分布
   - Bug 發現階段分布
   - 平均修復時間

### 3. compare_versions.py - 生成比較報告

**功能**：分析所有數據並生成完整的比較報告

**使用方式**：

```bash
cd comparison/scripts

# 生成預設報告
python compare_versions.py

# 指定輸出檔名
python compare_versions.py --output my_report.md

# 指定格式（目前只支援 markdown）
python compare_versions.py --format markdown
```

**輸出**：
- `comparison/analysis/comparison_report.md`

**範例輸出**：
```
==================================================
📊 開始生成比較報告
==================================================

✅ 報告已儲存：../comparison/analysis/comparison_report.md

==================================================
✅ 報告生成完成！
==================================================
```

**報告內容**：
1. 開發時間比較
   - 總開發時間
   - 平均功能開發時間
   - 開發時間分析

2. 程式碼品質比較
   - 程式碼規模
   - 程式碼複雜度
   - 程式碼品質分析

3. 測試覆蓋率比較
   - 覆蓋率統計
   - 覆蓋率分析

4. Bug 統計比較
   - Bug 總數與修復時間
   - Bug 分析

5. 綜合評分
   - 各項指標得分
   - 總結（優缺點）

6. 建議

## 📅 完整工作流程

### 第一週：初始化

```bash
# 1. 建立資料夾結構
mkdir -p comparison/metrics
mkdir -p comparison/analysis/charts
mkdir -p comparison/scripts

# 2. 複製模板和腳本
# （如上述步驟）

# 3. 安裝套件
pip install pandas matplotlib seaborn radon --break-system-packages
```

### 第二-三週：開發中

```bash
# 每完成一個功能，手動記錄到 CSV
# development_time.csv
# bug_tracking.csv（發現 Bug 時）

# 每週五，收集程式碼指標
cd comparison/scripts
python collect_metrics.py --all
```

### 第四週：生成報告

```bash
cd comparison/scripts

# 1. 收集最終指標
python collect_metrics.py --all

# 2. 生成所有圖表
python generate_charts.py

# 3. 生成比較報告
python compare_versions.py

# 4. 查看結果
open ../analysis/charts/  # 查看圖表
open ../analysis/comparison_report.md  # 查看報告
```

## 🔧 常見問題

### Q1: 執行 collect_metrics.py 時找不到 radon

**解決方式**：
```bash
pip install radon --break-system-packages
```

如果還是不行，腳本會自動使用簡單的計算方式（不影響使用）。

### Q2: 圖表中文顯示為方框

**解決方式**：
修改 `generate_charts.py` 的字體設定：
```python
# 在檔案開頭修改
plt.rcParams['font.sans-serif'] = ['你的中文字體名稱']
```

常見中文字體：
- macOS: `'Arial Unicode MS'`
- Windows: `'Microsoft YaHei'` 或 `'SimHei'`
- Linux: `'Noto Sans CJK'`

### Q3: CSV 檔案被 Excel 開啟後出現亂碼

**解決方式**：
使用 UTF-8 編碼開啟 CSV，或使用文字編輯器（如 VS Code）編輯。

### Q4: 路徑錯誤，找不到檔案

**檢查**：
1. 確認你在 `comparison/scripts/` 目錄執行腳本
2. 確認專案結構正確：
```
shopping-cart-comparison/
├── comparison/
│   ├── scripts/
│   │   ├── collect_metrics.py  ← 在這裡執行
│   │   └── ...
│   └── metrics/
│       └── *.csv
├── tdd-version/
├── bdd-version/
└── ddd-version/
```

## 💡 進階使用

### 自訂圖表樣式

編輯 `generate_charts.py`：
```python
# 修改顏色
colors = ['#你的顏色1', '#你的顏色2', '#你的顏色3']

# 修改圖表大小
fig, ax = plt.subplots(figsize=(寬, 高))

# 修改字體大小
plt.rcParams['font.size'] = 12
```

### 新增分析指標

1. 在對應的 CSV 模板新增欄位
2. 修改 `compare_versions.py` 的分析函數
3. 修改 `generate_charts.py` 新增圖表

### 匯出 HTML 報告

雖然目前腳本只支援 Markdown，但你可以使用工具轉換：

```bash
# 使用 pandoc 轉換
pip install pandoc
pandoc comparison_report.md -o comparison_report.html

# 或使用線上工具
# https://markdowntohtml.com/
```

## 📝 數據記錄建議

### 開發時間記錄
- **時機**：每完成一個方法就立即記錄
- **格式**：使用 24 小時制（如 14:30）
- **備註**：記錄遇到的問題、重構次數

### Bug 追蹤記錄
- **嚴重性**：Critical / High / Medium / Low
- **發現階段**：開發中 / 測試中 / 整合後
- **描述**：簡短但清楚

### 程式碼指標收集
- **頻率**：每週五下午
- **方式**：使用自動化腳本
- **檢查**：確認數據合理

### 測試覆蓋率記錄
- **TDD**：每次測試通過後記錄
- **BDD**：每個場景完成後記錄
- **DDD**：每週記錄一次
